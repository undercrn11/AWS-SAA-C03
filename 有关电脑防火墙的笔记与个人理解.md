### 有关电脑防火墙的笔记与个人理解



**Firewall Concepts & Evolution - Full Review**

1. **Historical Start - Firewalls as ACLs**
**Early firewalls were essentially Access Control Lists (ACLs) applied on routers.**
**ACLs worked by allowing or denying traffic based on: IP address, Port number, Protocol.**
**These operated at OSI Layer 3 (Network) and Layer 4 (Transport).**
**So yes - it's correct that early firewalls were developed as ACL systems.**
2. **Modern Firewall Scope - From Network to Application Layer**
**Modern firewalls inspect traffic from:**
- **Layer 3 (IP): Filtering based on IP addresses.**
- **Layer 4 (Port/Protocol): Filtering TCP, UDP, ports.**
- **Layer 5 (Session): Tracking connection state.**
- **Layer 6 (Presentation): SSL/TLS decryption.**
- **Layer 7 (Application): Deep packet inspection, analyzing app-level data.**





#### the thinns behind the scenes:

### The firewall **intercepts** the traffic

It works **like a security checkpoint**:

- It **sits in the path** between the user and the internet.
- It **monitors all traffic**, even though the browser never “talks” to it directly.
- It **inspects**, **filters**, or even **blocks** traffic **before it reaches the destination** (or the user's browser receives a response).

------

### 👇 Think of it like this:

Imagine the browser is sending a **letter to a friend (a website)**.

- It puts it in the mailbox (network).
- But **before** the letter leaves your house (network gateway), there’s a **security guard (firewall)** who opens the letter, reads it, and decides:
  - ✅ Let it go
  - ❌ Block it (malicious site, banned domain)
  - 🚧 Modify or log it (e.g., for auditing)

------

### 🔍 So, is the firewall just “watching” until needed?

Yes and no:

- It **reads (inspects)** every message **in real time** as it passes through.
- It's not passive — it actively **checks every packet or session**.
- If a rule is matched (e.g., block port 21), it takes action **immediately**.
- Otherwise, it lets it pass.

> 🔸 The browser sends requests normally — it doesn't “know” about the firewall.
>  🔸 The firewall is placed **in the path** of the traffic and **intercepts** everything automatically.
>  🔸 It doesn't “wait” in idle mode — it’s always monitoring and filtering based on rules.







3. **Real-World Example - User Uses Browser to Visit a Website**
**Scenario: A user opens Chrome and visits https://example.com.**
**Each OSI layer is involved in the process, and the firewall intercepts traffic:**

### Step-by-Step (with Browser + Firewall Role)

| OSI Layer                  | Who’s Acting?                    | What Happens                                                 | What the Firewall Does                                       |
| -------------------------- | -------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **Layer 7 – Application**  | **Browser (Chrome/Edge)**        | User types `https://example.com` into the address bar. The browser sends an **HTTP GET** or **HTTPS request**. | 🔒 Firewall inspects app data (e.g., is this a banned website? Is there malicious code in the request?) |
| **Layer 6 – Presentation** | **Browser**                      | Browser encrypts the request using **TLS/SSL** (for HTTPS).  | 🔒 Advanced firewall may decrypt the HTTPS traffic (if configured) and scan it for malware or data leaks. |
| **Layer 5 – Session**      | **Operating System / TCP stack** | Establishes a TCP session with `example.com` (e.g., TCP handshake). | 🔒 Firewall checks session state. Only allows packets that are part of **legitimate sessions** (e.g., prevents spoofed or unauthorized sessions). |
| **Layer 4 – Transport**    | **OS + Browser**                 | Sends data via **TCP port 443** (HTTPS) or port 80 (HTTP).   | 🔒 Firewall allows or blocks based on **port rules** — e.g., allow port 443, deny port 21 (FTP). |
| **Layer 3 – Network**      | **Operating System**             | Gets the destination IP of `example.com` via DNS and starts IP-based routing. | 🔒 Firewall checks source and destination **IP addresses** and can block traffic from or to malicious IPs. |
| **Layer 2 – Data Link**    | **Network Interface**            | Breaks data into Ethernet frames, adds MAC addresses.        | (Firewall usually doesn't act here unless it’s a combined device like a L2/L3 switch.) |
| **Layer 1 – Physical**     | **Ethernet/Wi-Fi card**          | Bits travel over cable or Wi-Fi.                             | N/A (Firewall sees it once it’s Layer 3+.)                   |

------

### 🧠 So, although the **user only interacts with the browser**, the firewall is:

- 🕵️‍♂️ Inspecting packets invisibly in the background
- 🚨 Blocking threats or disallowed sites even if the user tries to access them
- 🔐 Managing encrypted sessions to make sure nothing harmful sneaks through





5. #### **Generations of Firewalls**

### **1st Gen – Packet-Filtering Firewalls** (Late 1980s)

- **Checks:** IP addresses, protocols, and ports.
- **Layer:** OSI Layer 3 (Network) and Layer 4 (Transport).
- **How it works:** Simple rules like “allow port 80 from this IP.”
- **Limitations:** No awareness of connection state or applications.

------

### ✅ **2nd Gen – Stateful Firewalls** (Mid 1990s)

- **Adds:** Connection state tracking (Is it part of an established session?).
- **Layer:** Still L3/L4 but with **session awareness** (Layer 5).
- **How it works:** Knows if a packet is part of a valid session or not.
- **Improvement:** Can detect abnormal behaviors like TCP SYN floods.

------

### ✅ **3rd Gen – Application-Layer (Proxy) Firewalls** (Early 2000s)

- **Adds:** Deep Packet Inspection (DPI), can understand HTTP, FTP, DNS, etc.
- **Layer:** Up to OSI Layer 7 (Application).
- **How it works:** Reads the actual content of packets (e.g., see HTTP requests).
- **Use case:** Block websites, scan for viruses, detect app-specific attacks.

------

### ✅ **4th Gen – Next-Generation Firewalls (NGFW)** (2010s – Now)

- **Adds:**
  - Intrusion prevention (IPS)
  - Behavior-based detection
  - App control (e.g., block Facebook but allow LinkedIn)
  - SSL inspection
  - Identity-based access (link traffic to users)
- **Layer:** Full stack (L3–L7).
- **Uses:** AI/ML in modern systems for threat detection.
- **Often cloud-based**, or hybrid with on-prem deployment.



- **5th Gen firewalls** (emerging term): Often refers to **integrated, cloud-native, AI-driven**, and **zero-trust-based** systems.
  - Still developing, but some vendors (e.g., Check Point, Palo Alto) use this term.
