# 有关物流仓储系统的概要认识



![屏幕截图 2024-11-28 101504](C:\Users\msduser\Pictures\Screenshots\屏幕截图 2024-11-28 101504.png)

这张图展示了一个 **仓库控制系统（WCS）** 的架构，该系统与 **仓库管理系统（WMS）** 和 **可编程逻辑控制器（PLCs）** 集成，用于控制各种仓库自动化设备，例如传送带、起重机和机器人。

WCS = Warehouse Control System

WMS = Warehouse Management System

------

### **图中关键组件说明**

1. **WCS架构（系统核心）：**
   - WCS-DB：
     - 管理数据库交互。
     - 可能存储与仓库操作相关的实时数据（例如库存状态、任务分配等）。
   - WCS-PLC：
     - 负责与PLC的通信。
     - 使用TCP/IP协议（DB或SLMP）与 **主PLC（西门子和三菱）** 通信。
     - 充当WCS和硬件设备（如传送带、机器人、起重机）之间的中介。
   - Watch Dog（看门狗）：
     - 监控WCS中所有线程和组件的运行状态。
     - 如果组件发生故障，会发出警报或尝试重启。
2. **PLC（硬件控制）：**
   - 主PLC：
     - 西门子PLC和三菱PLC分别连接不同的硬件设备（如起重机、传送带、机器人）。
     - 每个PLC负责管理一组设备以执行任务，例如移动货物。
   - 通信协议：
     - 西门子PLC使用 **TCP/IP DB**。
     - 三菱PLC使用 **TCP/IP SLMP**。
3. **监控与控制系统：**
   - BCR-Control：
     - 可能是 **条形码阅读器控制模块（Barcode Reader Control）**，用于通过条码扫描识别和跟踪货物。
   - PID：
     - 表示 **比例-积分-微分控制器（Proportional-Integral-Derivative Controller）**，用于稳定和高效地控制系统流程，例如机器人移动或传送带速度(一种控制算法)。
   - AR-Monitor：
     - 可能是 **自动机器人监控模块（Automated Robot Monitor）**，用于实时跟踪和管理机器人操作。
   - Maintain-Monitor：
     - 负责监控系统维护任务，确保硬件运行正常，并在需要时发出维护警报。
4. **API控制：**
   - 允许外部系统或组件与WCS交互。
   - 可能提供用于实时监控或任务分配的接口。
5. **WMS集成：**
   - **WMS DB** 是一个高层系统，用于管理库存、客户订单和任务分配。
   - 通过接口与WCS集成，分配任务并更新库存状态。

------

### **数据流分析**

1. **从WMS到WCS：**
   - WMS通过接口将库存或任务数据发送到WCS。
   - WCS处理任务并将其分配给通过PLC控制的硬件设备。
2. **从WCS到PLC：**
   - WCS-PLC通过TCP/IP协议与西门子和三菱PLC通信，控制起重机、机器人和传送带等设备。
3. **反馈回路：**
   - 实时状态更新（例如货物位置、系统错误）从PLC返回到WCS，记录在数据库中，并由 **AR-Monitor** 或 **Maintain-Monitor** 监控。
4. **API交互：**
   - 外部系统或操作人员可以使用API控制或监控WCS操作。

------

### **架构优势**

- 模块化设计：
  - 不同组件（例如WCS-PLC、WCS-DB、监控模块）通过线程独立管理。
- 实时监控：
  - 像AR-Monitor和Maintain-Monitor这样的模块确保机器人和硬件健康状况的持续跟踪。
- 可扩展集成：
  - 能够通过标准化通信协议与多个PLC品牌（例如西门子和三菱）协作。
- WMS与WCS分离：
  - 任务由WMS分配，WCS负责执行，职责分工明确。

------

### **潜在瓶颈或问题**

1. 延迟：
   - WCS-PLC与主PLC之间的TCP/IP通信可能会在未优化的情况下引入延迟。
2. 线程依赖：
   - 如果一个线程失败（例如WCS-DB或BCR-Control），可能会中断操作。
   - 看门狗模块需要足够强大，以快速检测并恢复故障。
3. 人工叉车集成：
   - 如果使用人工叉车（而不是自动化系统），可能会降低输入/输出点的整体吞吐量。



### **Example: Storing a Cargo Item**

#### **Step 1: Task Initialization (WMS to WCS)**

1. **Customer Input in WMS:**
   - A customer logs into the Warehouse Management System (WMS) and inputs details of the cargo:
     - Cargo ID: `CARGO123`
     - Type: `Fragile`
     - Quantity: `10 units`
     - Preferred Zone: `Zone A`
   - WMS determines the best storage location based on availability and business rules, assigning **Zone A**.
2. **WMS Task Creation:**
   - WMS creates a **storage task** for the cargo and sends it to the WCS through the interface.
   - Task details:
     - Task ID: `TASK001`
     - Cargo ID: `CARGO123`
     - Target Zone: `Zone A`
3. **WCS Receives Task:**
   - WCS stores the task in the **WCS-DB** and begins processing it.

------

#### **Step 2: Cargo Arrival at the Warehouse**

1. **Cargo Arrival at Input Port:**
   - The cargo arrives at **Port 1** (input port for fragile items).
   - A **barcode scanner (BCR)** reads the cargo's barcode (`CARGO123`) and sends this data to the WCS.
2. **WCS Verifies Cargo:**
   - WCS matches the barcode information with the task (`TASK001`) in the database.
   - Confirms that `CARGO123` is expected at **Port 1** and needs to be stored in **Zone A**.

------

#### **Step 3: Task Execution (WCS to PLC)**

1. **Robot Assignment:**

   - WCS assigns a robot (via the **AR-Monitor**) to transport the cargo from **Port 1** to **Zone A**.

   - Task details are sent to the robot through the

      

     Mitsubishi PLC (via TCP/IP SLMP protocol)

     :

     - Start Point: **Port 1**
     - End Point: **Zone A**
     - Cargo ID: `CARGO123`

2. **Robot Movement:**

   - The robot picks up the cargo at **Port 1**.
   - The WCS continuously monitors the robot's position via the **AR-Monitor**.
   - The robot moves along its designated path toward **Zone A**, avoiding collisions with other robots or obstacles.

------

#### **Step 4: Storage in the Designated Zone**

1. **Conveyor or Crane Assistance:**
   - Upon reaching **Zone A**, the robot places the cargo onto a **conveyor** or under a **crane**, depending on the storage configuration.
   - The **Siemens PLC (via TCP/IP DB protocol)** activates the conveyor or crane to lift and place the cargo in its assigned location within **Zone A**.
2. **Confirmation:**
   - Once the cargo is stored, the PLC sends a confirmation signal to the WCS.

------

#### **Step 5: Task Completion (WCS to WMS)**

1. **Task Status Update:**

   - WCS updates the task status in the

      

     WCS-DB

     :

     - Task ID: `TASK001`
     - Status: `Completed`
     - Storage Location: `Zone A, Row 3, Shelf 5`

   - This status is sent to the WMS.

2. **WMS Confirmation to Customer:**

   - WMS notifies the customer that `CARGO123` has been successfully stored in **Zone A, Row 3, Shelf 5**.
   - The customer can now view the cargo's storage details in the WMS dashboard.

------

### **Detailed Flowchart**

Here’s the flow summarized as a series of steps:

1. **WMS Task Creation:**
   - Customer inputs storage requirements → WMS generates a task → Sends task to WCS.
2. **Cargo Arrival:**
   - Cargo arrives at input port → Barcode scanned → Data sent to WCS → WCS verifies cargo.
3. **Robot Assignment:**
   - WCS assigns robot → Sends task details to PLC → PLC controls robot movement.
4. **Cargo Placement:**
   - Robot transports cargo → PLC activates conveyor or crane → Cargo placed in storage.
5. **Task Completion:**
   - PLC confirms storage → WCS updates task status → WMS notifies the customer.
